## 咨询：能否用 gradio.app 发布本项目（YunGameWebLocation）

### 项目现状
- 纯静态单文件网页 `index.html`（986 行 / 约 42 KB），无构建、无后端、无 npm 依赖。
- 唯一外部依赖：高德地图 JS API `webapi.amap.com/maps?v=2.0`，key = `a01878acdecff250a4b69513defde872`（硬编码在第678 行）。
- 布局为全屏：`html,body { height:100%; overflow:hidden }`，`#map { position:absolute; inset:0 }`，侧边栏 380px 抽屉。
- 门店数据 `STORES` 数组直接内联在 `<script>` 中（西宁地区电竞门店，含 lat/lng）。
- 现有发布方式：GitHub Pages，仓库 `https://github.com/NemecSoft/weblocation.git`，用 `push.bat` 提交。

### 结论要点（供后续决策参考）
1. gradio.app 已不是 Gradio 的免费托管平台，官网仅剩文档站；永久托管在 Hugging Face Spaces。
2. `xxx.gradio.app` 是 `launch(share=True)` 的临时链接，**7 天过期**。
3. 2026-07 起 HF 创建 Gradio / Docker Space 需付费（个人 PRO $9/月）；免费账号仅 Static Space 免费 + 2 个 ZeroGPU。
4. Gradio 会套自身 UI 壳，全屏 `inset:0` 布局在 iframe 内会被裁切，体验打折。
5. 换域名后高德 key 需去控制台加白名单，否则地图白屏。

### 顺带实测：voxcpm.modelbest.cn 托管架构
用户以为该站托管在 gradio.app，实测结论为**完全自建**：
- DNS：`voxcpm.modelbest.cn` → `124.70.50.249`（华为云 AS55990，北京）；`modelbest.cn` → CNAME `x0lcbomnuljcb7i6e67gmulocztmz5f2.yundunwaf3.com`（阿里云云盾 WAF，39.107.194.139）。
- 响应头：`server: nginx/1.31.5`。
- 访问 `/config` 返回 `{"version":"6.10.0","mode":"blocks",...}`，确认是Gradio 6.10.0 自建部署，非 HF Spaces。

### 建议方案（待用户选择）
- 首选 Cloudflare Pages：连 GitHub 仓库即可，零代码改动、免费、不休眠。
- 次选 HF Static Space：免费拿 hf.space 域名，但需在 README 加 YAML frontmatter（sdk: static），国内访问慢。
- Gradio 路线：不推荐（付费 + 布局裁切）。

### 待办 / 风险
- 高德 key 若有域名白名单，换任何新平台前需先在控制台加白名单。

### 过程中的两个坑（已写入用户级 MEMORY.md）
1. 首次 clone 报`schannel: CRYPT_E_NO_REVOCATION_CHECK` → `git config --global http.schannelCheckRevoke false` 解决。
2. `heygen-com/hyperframes` 直连 clone 反复失败（remote end hung up / invalid index-pack output），`ghfast.top` 镜像同样失败。
   **最终解法**：用 `data.jsdelivr.com/v1/packages/gh/heygen-com/hyperframes@main?structure=flat` 拿文件树 JSON，
   发现 `hyperframes-cli` 只有 1 个文件，直接从 `cdn.jsdelivr.net/gh/heygen-com/hyperframes@main/skills/hyperframes-cli/SKILL.md` 下载即可。
   → 教训：**拉取单个 skill 不要 clone 整个仓库**，先查文件树，按需下载，快且稳。
